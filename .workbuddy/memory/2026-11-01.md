# 2026-11-01

## 修复「导出 PDF 没反应」（docx-html playground + examples/browser.html）

- 现象：示例页点「下载 PDF」无任何反馈；「下载 HTML」正常。
- 排查结论：不是 `convertToPdf` 报错。Playwright（headless Chrome，5178 dev / 4173 preview / file:// 三种入口）均能成功产出 PDF。真正的差异在于 HTML 下载在 click 里同步触发，而 PDF 要等几秒的异步生成，浏览器会把后者的 `a.click()` 当成自动下载而静默丢弃；两种情况页面上都没有任何提示。
- 改动（5 个文件）：
  - `apps/playground/downloads.ts`：`download()` 现在返回 `{ url, name }`，blob URL 保留 10 分钟供兜底点击。
  - `apps/playground/ui/view.ts`：新增 `saved(message, file)`，在状态栏渲染「未自动下载请点此保存」链接。
  - `apps/playground/controller.ts`：HTML/JSON/PDF/资源包统一走 `view.saved()`；PDF 提示里带体积，例如「PDF 已生成（137 KB）」。
  - `examples/browser.html`：点 PDF 立即显示「正在生成 PDF…」，完成后状态给出体积 + 兜底链接；三个下载共用 `saveBlob()`（锚点先挂到 DOM 再 click，兼容 WebKit）。
  - `apps/playground/styles.css`：`.status-row a` 样式。
- 验证：`npm test` 63 passed；`playwright test browser.spec.ts` 10 passed；`pdf.spec.ts` 关键 2 条通过；2.8 MB 真实文档导出 20 MB PDF 约 4s。

## 构建注意（既有问题）

`npm run build` 的 typecheck 依赖 `dist/*.d.ts`（tests/e2e/pdf.spec.ts 直接 import `../../dist/node.js`）。若先清空 dist 再 build 会报 `convertToPdf does not exist`。绕过：先 `vite build --config vite.lib.config.ts` + `tsc -p tsconfig.build.json` 生成声明，再跑 typecheck 与其余 build。
